# 动效生命周期规范

## Purpose

统一 Tween、Animator、Animation、Spine、粒子和飞行动效的开始、完成、中断、复用和失败行为，避免状态残留、资源泄漏、重复回调和旧表现影响新界面或新关卡。

## Applies When

- 接入或修改 UI Tween、面板进出场、角色动画、一次性粒子、循环特效或飞行动效。
- 动效需要与奖励、结算、销毁、对象池、场景切换或异步流程协作。
- 修复重复播放、回调越界、关闭后继续运行或复用状态错误。

## Decision Process

实现前定义：触发条件、是否允许并发、初始状态、视觉终点、正常结束、中断条件、坐标系、时间尺度、所有者和失败降级。

根据表现选择项目已经使用的系统：简单属性变化优先使用现有 Tween；完整时间轴优先 Animator、Animation 或 Spine；高频独立短特效再评估对象池。不要在一个简单表现中混用多套系统。

## MUST

- 核心业务结果必须独立于动效成功播放；奖励、状态写入、关卡完成等不能只依赖完成回调或 Animation Event。
- 播放动效的所有者必须同时负责停止、取消、清理和失败降级，不能只实现开始路径。
- 每次播放前必须恢复确定的初始状态，不能依赖上一次播放自然停留的位置、透明度、缩放或动画状态。
- 再次触发、界面关闭、对象禁用、回池、切关或目标消失时，旧 Tween、协程、异步回调和监听必须停止或失效。
- 完成回调必须最多执行一次；并发的正常完成与中断清理必须有幂等保护。
- 可复用对象的异步完成必须校验当前代次、取消令牌或等价身份，防止旧回调操作新的使用周期。
- 临时表现对象必须由生命周期足够长的面板或表现控制者管理，不能依附于即将销毁或回池的触发对象。
- 获取资源或表现实例失败时，必须保证核心业务能够继续到达合法状态。

## SHOULD

- 应该沿用相邻模块已有的动效系统和面板进出场机制。
- 应该保存 Tween、播放任务或监听句柄，并在生命周期出口清理。
- 一次性粒子应该根据实际有效粒子的播放状态判断完成，不用与资源配置脱节的固定延时猜测。
- 循环动效应该提供对称的开始与停止入口，由明确业务状态结束。
- 应该在统一位置配置时长、曲线和延迟，避免多个调用点复制魔法数字。
- 同屏大量表现应该验证粒子数量、Overdraw、材质数量、首次加载和池扩容尖峰。

## CONSIDER

- 动效受暂停影响时，明确选择缩放时间或非缩放时间。
- 目标会移动的飞行动效，明确锁定起始目标位置还是实时追踪。
- 同类动效重复触发时，明确重播、忽略、合并还是并发。
- 高频独立特效考虑对象池；面板中常驻节点直接复用，通常不需要额外池化。

## AVOID

- 避免同时运行多个动效系统写入同一属性而不定义覆盖关系。
- 避免只实现自然完成，不处理关闭、重进、切关和复用。
- 避免把临时特效挂到即将回收的业务对象下。
- 避免无差别清空共享表现层；只清理当前功能拥有的实例。
- 避免在逐帧回调中加载资源、搜索层级或频繁分配集合。

## Validation

- [ ] 首次、连续、快速重复和允许的同帧并发均符合预期。
- [ ] 初始状态和最终视觉状态确定。
- [ ] 正常完成回调只执行一次。
- [ ] 中途关闭、目标消失、切关和对象回池会正确停止或失效。
- [ ] 重开或复用后没有上一次的状态、监听和异步工作残留。
- [ ] 表现失败不会阻止核心业务完成。
- [ ] 时间尺度、分辨率、层级和遮挡符合需求。
- [ ] 性能敏感场景已在代表性设备和真实负载下验证。

## Project Questions

- 项目现有 Tween、动画、粒子和对象池系统是什么？
- 谁拥有动效生命周期，哪些出口会中断它？
- 核心业务是否错误依赖表现完成？
- 动效是否允许并发、受 `timeScale` 影响或跨场景存在？
