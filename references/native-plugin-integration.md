# 原生插件接入与验证

## Purpose

区分托管代码、原生二进制、构建产物和设备行为的验证范围，保持 SDK 来源和本地适配可追溯。资源身份与导入基础检查见 [资源与生成文件](assets-and-generated-files.md)。

## Applies When

- 导入、升级、裁剪或重建含平台原生库的 Unity SDK。
- 修改平台 PluginImporter、程序集依赖、Manifest、链接或原生库兼容配置。
- 排查 Editor 可运行但 Player 构建、链接或设备调用失败的问题。

纯 C# 包不强制执行原生库检查；只调用已有稳定 SDK 的业务改动，按实际影响选择验证层级，不默认重建上游库。

## Workflow

1. 记录官方来源、版本/提交、归档校验值、许可证、运行依赖和本地差异；按项目授权选择导入或适配范围。
2. 检查托管程序集、平台条件编译、原生架构、导入平台及运行模板等依赖；示例可排除，运行依赖不能当作示例删除。
3. 配置与源码适配保持最小范围，记录可重现的工具链和构建输入；不为消除可选依赖而无依据改变项目全局架构。
4. 分层验证：Editor 导入/编译 → 目标平台托管编译 → 原生库加载/链接 → 最终包检查 → 目标设备实际功能。按风险选择适用层，未执行层明确保留。

## MUST

- 必须保留所需运行依赖、许可证和资源身份，区分上游内容与本地修改；不能仅凭 Editor 调用安全跳过判定移动端功能通过。
- 平台二进制适配必须检查目标架构、导出接口、依赖与导入设置；涉及对齐或打包要求时分别检查库本身及最终包，不以构建配置代替二进制或包检查。
- 重建原生库时必须记录来源、工具链、依赖锁定及构建参数，并校验公共接口和相关行为；不能只改文件头或元数据伪造兼容结果。
- 校验通过、目标脚本编译、独立原生回归和游戏内设备功能必须分别报告；静态检查和替代回调不能证明触感、音频或其他真实硬件行为。
- 当前平台要求及系统兼容结论必须按任务时的官方说明核实，不把项目历史 SDK 版本、ABI 或系统数值写成所有项目的固定要求。

## Validation

- [ ] 上游来源、许可证、运行依赖和本地差异明确。
- [ ] 本次涉及的程序集、导入平台、架构、接口和链接依赖已核对。
- [ ] 重建可复现，最终产物与必要的行为已检查。
- [ ] 按实际影响完成对应构建与设备验证，各层未执行项单独列出。

## Validation Cases

- 正向：替换某平台原生库，校验接口和依赖，再验证目标包及设备调用，不以 Editor 编译作最终验收。
- 反向：纯 C# 库或未改 SDK 的普通调用点调整，不强制重建原生库和全部平台。
- 边界：没有目标设备或构建环境，完成可执行的编译/产物检查，明确设备行为与完整构建尚未验证。
