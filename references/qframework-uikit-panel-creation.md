# QFramework UIKit 面板创建

## Purpose

通过项目既有 UIKit 创建与绑定工具生成面板，让 Prefab、脚本、Designer 和资源路径配套，保持编辑器所见即所得。

## Applies When

- 项目使用 QFramework UIKit，需要创建弹窗/全屏面板，或审查、说明面板创建流程。
- 新增 Prefab 与脚本配对、Bind 字段、生成的 Designer 引用。

其他 UI 架构不套用本菜单和生成流程。面板视觉、布局及效果图验收同时执行 [UI 与 Prefab 规范](ui-and-prefab.md)；需要 ResKit 加载时执行 [QAssets 生成](qframework-reskit-generation.md)。

## Workflow

1. 检查同类面板、UIKit 版本、创建窗口和项目约定。确认是弹窗还是全屏 UI、应继承的基类、命名规则、命名空间、脚本和 Prefab 输出目录。
2. 使用目标项目已有面板创建工具。常见流程是打开 QFramework 设置窗口，选择 `UIKit 设置` / `UI Kit 设置`，再填写面板名并点击 `创建 UI Panel`（部分项目文档简称“创建UIPanel”）；菜单名称以当前实现为准，不假定所有 QFramework 版本均有此入口。
3. 保留窗口中已配置的输出路径，不为单个面板临时改成新目录。若已有配置与任务明确要求不一致，先查原因和影响，不盲目沿用也不擅自覆盖。
4. 按项目约定命名。采用 `PanelPopXXX` / `PanelXXX` 约定时，前者用于弹窗、后者用于全屏面板，不另造前缀；没有该约定的项目沿用其既有名称。
5. 等待生成与 Unity 导入，核对主脚本、Designer、Prefab、`.meta`、类名、根节点和面板标识相互一致。不要只看到脚本就认定面板已完成。
6. 在 Prefab 内搭建稳定节点与组件，通过 Bind 及 UIKit 生成流程更新字段，在业务脚本中直接使用绑定字段。纯装饰不必暴露给脚本；动态列表沿用已有 Cell/列表结构。
7. 检查编译、Console、Prefab 绑定，按真实业务入口验证打开、关闭和重开；涉及资源和视觉时追加对应规范的验证。

## MUST

- 必须使用项目已有创建/绑定生成链路，普通任务不手写 Designer 来代替生成。
- 固定 UI 对象和组件必须落在 Prefab，并使用生成绑定；不得用运行时 AddComponent、按名称 Find 或遍历子节点获取组件弥补缺失的固定结构。
- 不未经要求移动生成文件或更改全局输出目录；确需调整时先确认所有引用、资源标记和已有面板的影响。
- 生成失败先检查配置、模板、工具及导入错误，不创建一套旁路面板框架掩盖问题。
- Editor/菜单不可用时，说明具体待操作步骤和未生成/未验证内容，不伪称创建、编译或视觉验收完成。
- 模板默认值不能覆盖明确效果图要求；验收门槛见共享 UI 规范，不在本流程另设近似标准。

## Validation

- [ ] 面板类型、命名、基类和输出目录来自当前项目约定。
- [ ] 使用已确认创建入口，未无故改全局路径或移动生成文件。
- [ ] Prefab、主脚本、Designer、`.meta` 和绑定完整，生成结果可重新生成。
- [ ] 固定节点在 Prefab 中可见，无运行时结构补丁或名称查找绕过。
- [ ] Unity 编译、导入、真实入口打开/关闭/重开已验证；适用的资源和视觉验收已完成，或明确列出未验收项。

## Validation Cases

- 正向：在约定使用 PanelPop 前缀的项目创建奖励弹窗，保留输出配置，生成配套文件、绑定并验证真实入口。
- 反向：仅修复既有面板的计算逻辑，不重新创建面板；UI Toolkit 项目不强行引入 UIKit。
- 边界：定制菜单缺失或输出路径可疑，先定位实际工具与配置，不按别的项目路径创建；绑定字段缺失时修正 Prefab 并重新生成，而非手补 Designer。
